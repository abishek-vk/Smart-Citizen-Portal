# Smart Citizen Portal

A digital front door for city services. Citizens can pay property and water tax, report civic issues, apply for certificates, book parking and garbage pickup, explore transport, parks and libraries, and ask **Karen**, the built-in AI assistant. Every request can be tracked from one dashboard. Administrators get a separate console to manage complaints, certificates, citizens, reports and audit logs.

The interface is available in **English and Tamil**, works on phones and desktops, and supports light and dark themes.

---

## Features

### For citizens

| Area | What you can do |
|---|---|
| Dashboard | See outstanding tax, open complaints, pending certificates, upcoming payments and recent activity |
| Complaints | Report potholes, streetlights, dumping and more; follow every status change |
| Taxes | View and pay property and water tax bills, download receipts, use the tax calculator |
| Payments | Pay through a sandbox payment gateway (card with OTP, UPI, net banking); full payment history |
| Certificates | Apply for birth and death certificates and track approval |
| Garbage pickup | Book special waste collection in a time slot |
| Parking | Check live availability across city lots and reserve a spot |
| Transport | Browse bus, metro and tram routes with delay alerts |
| Parks and libraries | Find parks and amenities; search the library catalogue and borrow books |
| Karen (AI assistant) | Ask questions about city services in English or Tamil |
| Notifications and feedback | Get status alerts; rate services |

### For administrators

- Admin dashboard with city-wide metrics
- Complaint management (status, priority, assignment)
- Certificate approval queue
- Citizen directory
- Revenue and service reports
- Audit log of every write action, with filtering and pagination

## Prerequisites

- **Node.js 20.19 or newer** (required by Vite 7)
- **pnpm 9 or newer** (the repo refuses npm and yarn installs)
- **A PostgreSQL database**, for example a free [Supabase](https://supabase.com) project
- **A [Clerk](https://clerk.com) application** for sign-in
- *(Optional)* **A [Groq](https://console.groq.com) API key** for AI-generated answers from Karen, the assistant

## Getting started

1. Clone the repository.

   ```bash
   git clone https://github.com/abishek-vk/Smart-Citizen-Portal.git
   cd Smart-Citizen-Portal
   ```

2. Install dependencies.

   ```bash
   pnpm install
   ```

3. Create your environment file from the template.

   ```bash
   cp .env.example .env
   ```

4. Fill in `.env`. At minimum set `DATABASE_URL`, `CLERK_SECRET_KEY`, `CLERK_PUBLISHABLE_KEY` and `VITE_CLERK_PUBLISHABLE_KEY` (see [Environment variables](#environment-variables)).

5. Create the database tables from the Drizzle schema.

   ```bash
   pnpm --filter @workspace/db run push
   ```

6. *(Optional)* Load sample departments, plus parking lots, transport routes, parks and libraries for 10 Tamil Nadu districts.

   ```bash
   pnpm --filter @workspace/api-server run seed
   ```

   To refresh only the district data after editing `artifacts/api-server/src/data/tamil-nadu-districts.ts`, run `pnpm --filter @workspace/api-server run seed:districts`. It is safe to run more than once.

7. Start the API and the web app together.

   ```bash
   pnpm dev
   ```

8. Open **http://localhost:5173** and create an account.

The API runs on **http://localhost:5000** by default. Use `pnpm dev:api` or `pnpm dev:web` to start just one of them.

### Expected outcome

You land on the citizen dashboard after signing up. Tax bills are generated automatically for new accounts, so you can try paying one straight away (see [Sandbox payment gateway](#sandbox-payment-gateway)).

## Environment variables

All variables live in a single `.env` file at the repository root. Both the API and the web app read it.

| Variable | Required | Description |
|---|---|---|
| `DATABASE_URL` | Yes | PostgreSQL connection string (Supabase: *Project Settings → Database*) |
| `SUPABASE_DATABASE_URL` | No | Alternative name for the connection string; used if `DATABASE_URL` is empty |
| `PORT` | No | API port (default `5000`) |
| `BASE_PATH` | No | URL base path for the web app (default `/`) |
| `CLERK_SECRET_KEY` | Yes | Clerk secret key, used by the API |
| `CLERK_PUBLISHABLE_KEY` | Yes | Clerk publishable key, used by the API |
| `VITE_CLERK_PUBLISHABLE_KEY` | Yes | Same publishable key, exposed to the web app |
| `CLERK_PROXY_URL` | No | Clerk proxy URL, only if you use a Clerk proxy |
| `VITE_API_URL` | Production | Public URL of the deployed API. Defaults to `http://localhost:5000` in development |
| `VITE_API_BASE_URL` | No | Fallback for `VITE_API_URL` |
| `PAYMENT_GATEWAY_SECRET` | Production | Signs sandbox payment orders. Falls back to `CLERK_SECRET_KEY` if empty |
| `GROQ_API_KEY` | No | Gives Karen AI-generated answers. Without it, Karen falls back to built-in replies |
| `GROQ_MODEL` | No | Groq model name (default `llama-3.1-8b-instant`) |
| `ENABLE_SAMPLE_DATA` | No | Shows the *Demo Data / Seed Sample* tax buttons. On in development, off in production |
| `VITE_ENABLE_SAMPLE_DATA` | No | Frontend switch for the same buttons |

> **Never commit your `.env` file.** Only `.env.example` belongs in git.

## Admin access

Every new account is a **citizen**. To make someone an administrator, update their role in the database (for example in the Supabase SQL editor):

```sql
UPDATE users SET role = 'admin' WHERE email = 'you@example.com';
```

Valid roles are `citizen`, `admin` and `super_admin`. Sign out and back in, and you'll be taken to the admin console at `/admin`.

## Sandbox payment gateway

Tax payments go through a built-in **test-mode** gateway, modelled on Razorpay and Stripe test mode. No real money is ever charged.

How it works:

1. The app asks the API for an order. The server prices it from the bill itself and returns a signed order token that expires after 15 minutes.
2. The citizen pays with a card (followed by an OTP), UPI or net banking.
3. The API either marks the bill paid and issues a receipt, or records a failed payment in the history.

Use these test details:

| Method | Input | Result |
|---|---|---|
| Card | `4111 1111 1111 1111` or `5555 5555 5555 4444` | Success |
| Card | `4000 0000 0000 0002` | Declined |
| Card | `4000 0000 0000 9995` | Insufficient funds |
| Card OTP | `123456` | Any other OTP is rejected |
| UPI | `success@upi` / `failure@upi` | Success / declined |
| Net banking | Choose **Success** or **Failure** on the simulated bank page | As chosen |

Any future expiry date and any 3-digit CVV work. The checkout also has a **Test cards** panel that fills these in for you.

## Working on the API

The API contract lives in [`lib/api-spec/openapi.yaml`](lib/api-spec/openapi.yaml). To add or change an endpoint:

1. Edit `openapi.yaml`.
2. Regenerate the client and validators with `pnpm --filter @workspace/api-spec run codegen`.
3. Implement the route in `artifacts/api-server/src/routes/`, validating input with the generated schemas from `@workspace/api-zod`.
4. Register new routers in `artifacts/api-server/src/routes/index.ts`.
5. Call the endpoint from the web app with the generated hooks from `@workspace/api-client-react`.

All routes are served under `/api`. Protected routes use the `requireAuth` and `ensureUser` middleware in `artifacts/api-server/src/lib/auth.ts`. A quick health check is available at `GET /api/healthz`.

## Design system

The UI follows a clean, editorial style:

- **Type:** Inter for text, Anonymous Pro for small uppercase labels.
- **Color:** a deep indigo (`#1F1B6B`) primary on a white canvas.
- **Shapes:** pill-shaped buttons and inputs, and 20px rounded cards.

All colors are CSS variables in [`artifacts/citizen-portal/src/index.css`](artifacts/citizen-portal/src/index.css), defined for both light and dark mode. Change `--primary` there to re-theme the whole app.

Motion is built with Framer Motion and CSS scroll-driven animations. Shared animation components live in [`src/components/motion.tsx`](artifacts/citizen-portal/src/components/motion.tsx). All motion is disabled automatically when the user has *reduce motion* enabled in their device settings.

## Deployment

The web app and the API deploy separately.

- **Web app:** build with `pnpm --filter @workspace/citizen-portal run build` and serve `artifacts/citizen-portal/dist/public` as a static site. The included `vercel.json` rewrites all routes to `index.html` for client-side routing. Set `VITE_API_URL` and `VITE_CLERK_PUBLISHABLE_KEY` at build time.
- **API:** build with `pnpm --filter @workspace/api-server run build` and start with `pnpm --filter @workspace/api-server run start` on any Node host (Render, Railway, Fly.io, a VM). Set the database, Clerk, payment and Groq variables there.

Remember to add your production web URL to the allowed origins in your Clerk dashboard.

## Troubleshooting

- **"Use pnpm instead" during install.** The repo only supports pnpm. Install it with `npm install -g pnpm`.
- **"Missing VITE_CLERK_PUBLISHABLE_KEY".** The web app needs this variable in the root `.env` before it starts.
- **"DATABASE_URL … ensure the database is provisioned".** Set `DATABASE_URL` (or `SUPABASE_DATABASE_URL`) in the root `.env`.
- **Karen gives short, generic answers.** She's using her built-in fallback replies. Set `GROQ_API_KEY`, then restart the API.
- **The web app can't reach the API in production.** Check that `VITE_API_URL` was set when the web app was *built*, not only at runtime.
